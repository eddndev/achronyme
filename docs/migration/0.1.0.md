# Migrating from Achronyme 0.0.1 to 0.1.0

Achronyme 0.1.0 adds structured concurrency, precise effect manifests, owned
host resources, capability grants, and one semantic contract across the
interpreter, LLVM JIT, and AOT.

## Source compatibility

Existing sequential programs remain valid, with one lexical exception:
`concurrent`, `spawn`, and `await` are now reserved words. Rename variables,
parameters, or functions that used those identifiers. Parser diagnostics point
at the reserved identifier and request a rename.

Existing `read_line`, `read_file`, and `write_file` calls remain blocking
compatibility operations and do not require `await`. New owned file and TCP
operations suspend and must be explicit:

```ach
// 0.0.1 compatibility call
let text = read_file(path)

// 0.1.0 owned, suspending operation
let file = await open_file(path)
let bytes = await file_read(file, 4096)
await file_close(file)
```

Ordinary function declarations remain `fn`; there is no `async fn`. The
compiler infers task and host effects transitively. Add `await` at every call
site whose inferred behavior can suspend. A task-effect call may omit `await`
only as the direct operand of `spawn`; `cancel_check()` is the immediate
non-suspending exception.

## Host and provable code

0.1.0 makes the existing boundary stricter and transitive. `prove` and
`circuit` bodies reject task, console, file, network, clock, randomness, and
unknown-host effects even when reached through a helper function. Move host
work outside the provable body and pass only its deterministic value into the
proof boundary.

Provable array methods supported by 0.0.1 remain supported. In particular,
array `len()` inside a `prove` block is not a runtime-method chain and compiles
through the canonical provable-method catalog.

## Proving setup policy

0.0.1 could generate Groth16 or Plonkish parameters locally without making the
trust assumption visible. In 0.1.0 proof generation fails closed by default.
Select exactly one key source:

```text
# Local tests only; parameters are generated with local randomness.
ach --insecure-dev-setup run program.ach

# Production BN254 Groth16; the key must match the exact optimized R1CS.
ach --trusted-key-dir ./trusted-keys run program.ach
```

The production setting can also live in project configuration:

```toml
[proving]
trusted_key_dir = "trusted-keys"
```

There is no environment-variable acknowledgement that enables setup. The
effective mode appears as `proving.key_source` in `ach inspect --manifest`.
The trusted store is immutable and digest-addressed; create it only from a
verified phase-2 zkey with `ach trusted-setup package`.

Detached BN254 or BLS12-381 Groth16 artifacts can be checked with `ach verify`.
Production trusted-key import in 0.1.0 is limited to BN254 Groth16. BLS12-381
Groth16 and Plonkish proof generation require `--insecure-dev-setup` and must
not be represented as production proofs. Browser WASM has no proving setup or
filesystem authority.

See [the production trusted-setup guide](../proving/trusted-setup.md) and the
[ECDSA release gate](../proving/boss-fight-release-gate.md).

## Capability grants

File and network access is opt-in. Add the narrowest roots and numeric
addresses to the CLI invocation or project configuration:

```text
ach --allow-read ./inputs --allow-write ./outputs run program.ach
ach --allow-connect 127.0.0.1:443 run client.ach
```

```toml
[vm]
allow_read = ["inputs"]
allow_write = ["outputs"]
allow_connect = ["127.0.0.1:443"]
allow_listen = ["127.0.0.1:9000"]
```

Relative roots in `achronyme.toml` resolve from the project root. Paths are
canonicalized before access. Network entries must be exact numeric
`IP:PORT` values. Inspect the request before running:

```text
ach --error-format json inspect program.ach --manifest
```

The interactive CLI explicitly preserves console, clock, and randomness for
sequential compatibility. Embedders and WASM use the untrusted policy unless
they deliberately provide an adapter and grant.

## Resource and scheduler limits

Servers should choose limits instead of relying only on defaults:

```toml
[vm]
max_tasks = 128
max_resources = 128
max_task_scopes = 32
max_pending_native_requests = 64
max_retained_task_results = 64
max_channels = 64
max_channel_operations = 512
blocking_workers = 4
blocking_queue_capacity = 64
```

The same names are global CLI flags with hyphens. Capacity exhaustion is now a
recoverable error. Use bounded channels for backpressure and `bounded_server`
or `permit_pool` to cap active handlers.

Task handles are scope-bound and single-use. Replace any design that expects a
detached task with a lexical `concurrent` scope. Transfer an owned file,
listener, or connection to a spawned child only when the parent will no longer
use it. Explicit close is recommended; lexical cleanup remains deterministic.

## Artifact compatibility

The 0.1.0 compiler emits:

- ACHB container format `0x0d`, which adds canonical native metadata.
- register bytecode version 2, which adds structured task operations.
- append-only compiled runtime ABI version 6, which adds task control entries.

The runtime continues to load the canonical 0.0.1 pair: ACHB format `0x0c`
with bytecode version 1. Old artifacts receive the builtin metadata implied by
their legacy contract. Invalid format/bytecode pairs, malformed task control
flow, incomplete capability manifests, and incompatible compiled runtime ABIs
are rejected before execution.

Recompile source when moving an artifact into a 0.1.0-only deployment so its
precise effects, capabilities, cancellation behavior, and resource actions are
persisted. JIT cache identity includes the ACHB bytes, bytecode semantics,
runtime ABI, target data, and lowering revision, so a stale 0.0.1 task image is
not reused as 0.1.0 code.

## AOT environment

Standalone AOT executables receive grants and limits through explicit
environment variables:

- `AKRON_ALLOW_READ`, `AKRON_ALLOW_WRITE`
- `AKRON_ALLOW_CONNECT`, `AKRON_ALLOW_LISTEN`
- `AKRON_MAX_TASKS`, `AKRON_MAX_RESOURCES`, `AKRON_MAX_TASK_SCOPES`
- `AKRON_MAX_PENDING_NATIVE_REQUESTS`, `AKRON_MAX_RETAINED_TASK_RESULTS`
- `AKRON_MAX_CHANNELS`, `AKRON_MAX_CHANNEL_OPERATIONS`
- `AKRON_BLOCKING_WORKERS`, `AKRON_BLOCKING_QUEUE_CAPACITY`

Path lists use the platform path-list encoding. Address lists are comma
separated exact numeric addresses. Invalid values fail before program
execution.

## WASM

Browser WASM supports pure structured tasks, bounded in-memory channels,
cooperative yield, and captured virtual output. Timers, files, network,
console input, and randomness currently have no WASM adapters. They fail
capability preflight explicitly and do not receive browser or system authority.

## Verification checklist

1. Rename identifiers that use the three new reserved words.
2. Add `await` at every newly suspending call site.
3. Keep all host and task effects outside `prove` and `circuit` bodies.
4. Replace detached-work assumptions with a `concurrent` scope.
5. Add exact file and network grants.
6. Choose task, resource, channel, and blocking-pool limits.
7. Select a trusted key store or an explicit development-only setup mode.
8. Run `ach inspect --manifest` and verify both host grants and key source.
9. Verify detached release artifacts with `ach verify`.
10. Recompile ACHB and AOT artifacts for the 0.1.0 deployment target.
